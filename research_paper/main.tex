\begin{abstract}
Insider-threat detection requires behavioral context because malicious activity can be embedded in otherwise legitimate use of organizational systems. This paper presents \ThreatTron, a host-based detection platform that integrates heterogeneous endpoint telemetry, behavioral feature engineering, supervised and unsupervised learning, deterministic behavioral rules, explainable inference, and analyst-oriented investigation. The architecture joins a Windows endpoint agent, a FastAPI evidence backend, a Flask machine-learning service, and a React dashboard through session-linked event provenance. Network telemetry is data-minimized by recording connection metadata and salted SHA-256 endpoint digests rather than packet payloads. The behavioral model aggregates authentication, email, web, file, device, and host-context features into 33 model inputs. The saved version 0.3 pipeline combines LightGBM, Random Forest, logistic regression, and Isolation Forest scores using weights of 0.5, 0.2, 0.1, and 0.2, respectively. On the 1,000-user saved prediction artifact, 70 users carry positive pipeline labels and 61 exceed the configured 0.8 threshold; against that stored label field, the thresholded output yields 100.0\% precision, 87.14\% recall, 93.13\% F1, and 99.1\% accuracy. A separate observable-validation procedure identifies 61 of 191 listed insiders, providing a second view of alert coverage. Feature-level explanations accompany all 1,000 users, with the first-ranked feature dominated by file activity, device activity, and after-hours logons. The resulting system provides a reproducible, deployable framework for multimodal insider-threat triage while retaining explicit evidence provenance and interpretable risk decomposition.
\end{abstract}

\section{Introduction}
Insider threats differ from conventional perimeter attacks because the relevant activity often originates from authenticated users operating through legitimate applications, endpoints, and privileges. Detection therefore depends less on identifying a single malicious signature and more on recognizing combinations of timing, access, communication, file, device, process, and network behaviors. Surveys of insider-threat research repeatedly identify heterogeneous telemetry, extreme class imbalance, limited labels, behavioral drift, and interpretability as persistent challenges \cite{al-mhiqani2020,alzaabi2024,bhoi2026}.

A second challenge is operational. A useful detector must connect a statistical score to evidence that an analyst can inspect. Anomaly detection can surface previously unseen behavior, but rarity alone does not distinguish malicious activity from legitimate workload changes \cite{chandola2009}. Likewise, supervised models can learn discriminative patterns but depend on the coverage and quality of their labels. Explainability methods such as SHAP improve the visibility of model reasoning, although feature attribution should be treated as evidence for investigation rather than as a causal explanation \cite{lundberg2017,alketbi2025}.

\ThreatTron addresses these requirements as a systems-oriented architecture rather than as a new learning algorithm. The platform combines host telemetry from multiple behavioral domains, session-based evidence provenance, engineered user-level features, four complementary model signals, a rule-based behavioral layer, feature-level explanations, and an analyst workflow. The central design objective is to place detection, explanation, and evidence in one operational loop instead of treating machine learning as an isolated classifier.

The paper makes four contributions:
\begin{enumerate}
    \item a modular host-based architecture that joins endpoint collection, session provenance, backend evidence storage, hybrid risk inference, and analyst investigation;
    \item a 33-feature behavioral representation derived from authentication, email, web, file, device, and combined activity signals;
    \item a hybrid risk formulation that fuses supervised learning and unsupervised anomaly scoring, followed by deterministic behavioral corroboration in the live inference path; and
    \item an artifact-driven evaluation using the saved 1,000-user model outputs, threshold-level metrics, observable validation, and explanation coverage, together with an implementation description that supports reproducibility.
\end{enumerate}

\section{Research Context and Related Work}
\subsection{Behavioral Insider-Threat Detection}
The CERT Insider Threat Test Dataset is widely used because it provides heterogeneous activity streams and controlled insider scenarios for repeatable experiments \cite{cert2020}. Release r4.2 contains activity for 1,000 simulated employees and 70 malicious insiders, with logon, device, file, email, and HTTP sources forming a commonly studied benchmark \cite{cert2020}. Earlier and recent studies have used statistical modeling, classical classifiers, deep learning, and anomaly detection on these data. Yuan and Wu highlight the difficulty of learning insider behavior from high-dimensional, heterogeneous, sparse, and weakly labeled records \cite{yuan2021}; Alzaabi and Mehmood further identify temporal modeling and context-rich behavioral representations as important directions \cite{alzaabi2024}.

\subsection{Hybrid and Anomaly-Based Detection}
Anomaly detection is attractive when malicious examples are scarce, since the detector can learn a representation of normal behavior rather than requiring exhaustive threat labels \cite{chandola2009}. Isolation Forest is particularly suitable for tabular behavioral data because it assigns higher anomaly scores to observations that are isolated through random partitioning. However, anomaly scores are inherently context-sensitive. ThreatTron therefore complements anomaly detection with supervised LightGBM, Random Forest, and logistic regression models rather than treating novelty as synonymous with threat.

\subsection{Explainability and Analyst-Centered Detection}
Explainable AI has become an increasingly important research direction in insider-threat detection, with recent surveys identifying SHAP and LIME as common mechanisms for exposing feature contributions and supporting analyst trust \cite{alketbi2025}. ThreatTron's explanation layer applies SHAP TreeExplainer to the LightGBM component and persists the leading feature names associated with each user. This lightweight explanation representation is intentionally coupled to the investigation workflow so that a ranked score can be traced to the behavioral dimensions that caused the ranking.

\subsection{Positioning of ThreatTron}
The novelty of the system is primarily architectural and operational. Rather than proposing a new classifier, ThreatTron integrates heterogeneous host telemetry, data-minimized network metadata, user-level feature engineering, complementary supervised and unsupervised models, deterministic behavioral corroboration, explainability, and an evidence-linked workflow in a single deployable pipeline. This integration responds to a recurring gap in the literature: model studies frequently report predictive performance without describing how event provenance, analyst evidence, and deployment interfaces connect to the detection score \cite{al-mhiqani2020,alzaabi2024}.

\subsection{Endpoint Collection and Session Provenance}
The current agent uses Python-based collectors built around standard system interfaces. The process collector polls every 10 seconds, the network collector polls every 15 seconds, and system activity is sampled within the agent loop. File and USB collectors contribute event-driven activity. Every event carries an agent and session identifier, allowing analysts to associate events from different domains with the same collection interval and endpoint. The backend stores separate entities for agent sessions, file events, process events, system events, USB events, network events, and email events, as well as derived risk assessments, alerts, investigations, and investigation notes.

\subsection{Data-Minimized Network Telemetry}
The network collector records local and remote endpoint digests, ports, connection state, process identifier, and process name rather than packet payloads. Endpoint addresses are transformed with SHA-256 using the current application salt before the event is emitted. The collector also suppresses remote ports 80, 443, 53, and 123. This design lowers the sensitivity and volume of persisted network data while retaining enough structure to correlate connection behavior with process and session context. The use of a deterministic application salt makes the digests suitable for grouping repeated observations but not equivalent to anonymity.

\subsection{Evidence and Analyst Workflow}
ThreatTron separates raw telemetry from derived security workflow objects. An alert can therefore retain a reference to its supporting event evidence while an analyst records a disposition and investigation note. The backend exposes aggregated overview endpoints and recent-event queries, while the live risk endpoint attaches selected evidence references to each risk assessment. The workflow is designed around the sequence shown in Fig.~\ref{fig:workflow}: rank, explain, inspect evidence, record disposition, and retain feedback for subsequent calibration.

\section{Behavioral Feature Construction}
The saved version 0.3 pipeline aggregates user activity into 33 model inputs. The raw behavioral representation contains 17 fields, after which the feature-engineering stage adds 16 derived variables. Count features capture activity volume, while ratios reduce dependence on absolute workload and emphasize behavioral composition. The engineered representation is summarized in Table~\ref{tab:features}.

For user $u$, the feature vector is
\begin{equation}
\mathbf{x}_u = [x_{u1},x_{u2},\ldots,x_{u,33}].
\end{equation}

The main denominator is total activity,
\begin{equation}
A_u = L_u+E_u+H_u+F_u+D_u+1,
\end{equation}
where $L$, $E$, $H$, $F$, and $D$ denote logon, email, HTTP, file, and device activity, respectively. Representative ratios are
\begin{equation}
\rho_{\mathrm{after}}=\frac{L_{\mathrm{after}}}{L+1},\quad
\rho_{\mathrm{attach}}=\frac{E_{\mathrm{attach}}}{E+1},
\end{equation}
\begin{equation}
\rho_{\mathrm{file}}=\frac{F_{\mathrm{exe/arch}}}{F+1},\quad
\rho_{\mathrm{http}}=\frac{H_{\mathrm{suspicious}}}{H+1}.
\end{equation}

Composite measures include overall suspicious ratio, exfiltration intensity, activity intensity, after-hours file ratio, domain diversity, and recipient diversity. The implementation applies the same feature derivation at inference time, so the live API receives raw behavioral counts and reconstructs the engineered schema before model scoring.

\section{Hybrid Risk Inference}
\subsection{Complementary Model Components}
ThreatTron uses four model components selected for complementary behavior on structured activity data. LightGBM captures nonlinear feature interactions efficiently \cite{ke2017}. Random Forest provides a second tree-based view with randomized aggregation \cite{breiman2001}. Logistic regression supplies a lower-complexity linear reference. Isolation Forest models deviations from a normal behavioral baseline and is trained only on rows with label zero in the saved pipeline.

The supervised pipeline uses RobustScaler and an 80/20 stratified random partition with a fixed random seed of 42. LightGBM uses 200 estimators, maximum depth 8, and class balancing; Random Forest uses 100 estimators, maximum depth 8, and balanced class weights; logistic regression uses a maximum of 1,000 iterations and balanced class weights. Isolation Forest uses 150 trees and a contamination parameter of 0.02.

\subsection{Offline Ensemble Score}
For the reproducible batch path, each model output is transformed to a comparable $[0,1]$ score. Let $s_L$, $s_R$, $s_G$, and $s_A$ denote the normalized LightGBM, Random Forest, logistic, and anomaly scores. The configured ensemble is
\begin{equation}
R_{\mathrm{ML}}(u)=0.5s_L(u)+0.2s_R(u)+0.1s_G(u)+0.2s_A(u).
\end{equation}

The offline pipeline marks a high-risk user when $R_{\mathrm{ML}}>0.8$. The weights encode the relative contribution chosen for the saved experiment and provide a simple mechanism for threshold and sensitivity analysis.

\subsection{Operational Rule Corroboration}
The hosted inference path supplements the model score with seven deterministic behavioral rules. The rule engine detects USB-plus-file activity, suspicious-web-plus-file staging, external-email-plus-file activity, a combined USB/web/email chain, executable or archive creation, after-hours exfiltration, and mass external-recipient activity. The operational score is
\begin{equation}
R_{\mathrm{op}}(u)=0.5R_{\mathrm{ML}}(u)+0.5R_{\mathrm{rule}}(u),
\end{equation}
with the live threat threshold configured at $R_{\mathrm{op}}\geq0.45$. This second layer adds interpretable, high-level behavioral patterns to the statistical score without retraining the underlying models.

\section{Explainability and Evidence Correlation}
ThreatTron's explainability layer uses SHAP TreeExplainer on the LightGBM model. For each user, the implementation ranks feature attributions and persists the three feature names with the largest positive contributions. The artifact therefore produces a compact explanation record that can be joined to the user's risk score and underlying evidence.

For an analyst, this creates a direct path from model output to investigation hypothesis. A high contribution from file activity motivates inspection of file operations and the corresponding process or device context. A high after-hours signal motivates review of authentication timing and surrounding events. An external-email or suspicious-HTTP contribution directs attention to communication context. The interpretation is intentionally multi-source: a feature ranking selects evidence to inspect rather than replacing the evidence itself.

A session begins with a session-start event containing endpoint identity and timestamps. Subsequent records retain the same session identifier. The batch sender transmits structured event arrays to the backend, which maps each event type to its corresponding database entity. The implementation also separates operational telemetry from the offline research pipeline. Offline training operates on the CERT-derived behavioral artifact, while live inference operates on recent endpoint records and reconstructs the same engineered feature vocabulary. This separation allows the saved experiment to be reproduced without requiring the deployed services, while the deployed services provide the path needed to exercise the model in an endpoint workflow.

\section{Experimental Setup}
\subsection{Dataset and Saved Artifacts}
The model pipeline is configured for the CERT r4.2 dataset and produces a user-level table with 1,000 rows and 35 columns: one user identifier, one label, and 33 model features. The saved prediction artifact contains one row per user, four normalized model scores, a final risk score, and the stored label. The explanations artifact contains three ranked feature names for every user. CERT r4.2 is commonly used for insider-threat research because its 1,000-user population and controlled scenarios provide a repeatable experimental environment \cite{cert2020}.

The evaluation in this paper uses the repository's saved artifacts rather than recomputing results from an unavailable raw dataset. The repository records 70 positive labels in the prediction artifact and 61 users above the offline threshold of 0.8 \cite{threattronrepo}. This gives an exact, inspectable basis for evaluating the current implementation.

\subsection{Evaluation Measures}
For the stored prediction label field, the thresholded output can be summarized by true positives (TP), false positives (FP), false negatives (FN), and true negatives (TN):
\begin{equation}
\mathrm{Precision}=\frac{TP}{TP+FP},\quad
\mathrm{Recall}=\frac{TP}{TP+FN},
\end{equation}
\begin{equation}
F_1=2\frac{\mathrm{Precision}\cdot\mathrm{Recall}}
{\mathrm{Precision}+\mathrm{Recall}}.
\end{equation}

The saved threshold produces $TP=61$, $FP=0$, $FN=9$, and $TN=930$ against the prediction artifact's own label column. In addition, the repository includes a separate observable-validation report containing 191 listed insiders and 61 threshold captures. Reporting these two views separately prevents the stored pipeline-label evaluation from being confused with the observable comparison.

\section{Discussion and Future Research}
ThreatTron demonstrates that a relatively compact tabular representation can be embedded in a broader endpoint detection workflow without requiring a monolithic deep-learning architecture. The supervised ensemble captures labeled behavioral distinctions, Isolation Forest adds a novelty signal, and the rule engine provides deterministic patterns that are easy to inspect. Session identifiers provide the common key required to move from an abstract risk score back to the events that produced it. These properties make the architecture suitable for research settings where reproducibility and evidence traceability are as important as classifier selection.

The principal empirical result is therefore the consistency of the complete pipeline rather than a claim that one classifier is intrinsically superior. The 61-user high-risk set is small enough for analyst review, while the feature explanations provide a compact reason code for each user. The separate observable validation also shows why a single metric is insufficient: agreement with the stored model labels and coverage of an observable insider list answer different questions.

Several experiments follow naturally from the current implementation. A user-disjoint split would measure generalization to previously unseen users, while a time-ordered holdout would measure future-behavior detection under temporal drift. Ablation studies can remove one telemetry family at a time to quantify the marginal value of email, web, file, device, and authentication features. Calibration experiments can tune the 0.8 offline threshold and the live rule-fusion operating point against a specified alert budget. Finally, repeated-seed experiments and multi-environment evaluation can quantify stability when workload, population, and event prevalence change.

\section{Conclusion}
This paper presented ThreatTron, a host-based insider-threat detection architecture combining multimodal endpoint telemetry, session-linked evidence storage, engineered behavioral features, hybrid supervised and unsupervised inference, rule-based corroboration, explainability, and analyst-oriented investigation. The current implementation contains a 33-feature user-level behavioral model, four complementary learning components, seven operational behavioral rules, and a React/FastAPI/Flask deployment stack.

On the saved 1,000-user prediction artifact, 61 users exceed the configured offline threshold of 0.8, corresponding to 61 true positives, nine false negatives, and zero false positives against the artifact's stored labels. The resulting precision, recall, F1, and accuracy are 100.0\%, 87.14\%, 93.13\%, and 99.1\%, respectively. The separate observable-validation procedure captures 61 of 191 listed insiders, while the explanation artifact provides three leading feature names for every user and identifies file activity as the most frequent first-ranked feature.

The resulting contribution is a reproducible systems framework for turning heterogeneous endpoint behavior into an evidence-linked and explainable risk-ranking workflow. Its research value lies in the integration of collection, feature engineering, hybrid inference, explainability, and operational evidence handling in one implementation, providing a concrete base for subsequent temporal, calibration, ablation, and cross-environment studies.
